# REG Conformance Vector Collection

This directory contains machine-readable conformance vectors for the Runtime Execution Governance (REG) standard.

## Files

| File | Purpose |
|------|----------|
| `core.yaml` | Core validation scenarios (`C1`..`C5`) |
| `commit.yaml` | Commit-phase vectors (`CT-R4-001`..`CT-R4-010`) |
| `extended.yaml` | Extended conformance scenarios (`R0`..`R7`) |
| `proposals.yaml` | Candidate or non-validated proposals |
| `schema.json` | JSON Schema for validating vector structure |
| `compile.py` | Converts YAML vectors into the bundled JSON artifact |

## Vector Taxonomy

### Categories

- **core** (C1–C5): Foundational requirements for baseline REG compliance. Every runtime must satisfy these vectors.
- **commit** (CT-R4-001–CT-R4-010): Requirements for execution record integrity, audit trails, and persistence.
- **extended** (R0–R7): Advanced scenarios covering edge cases, failure modes, and distributed systems behavior.
- **candidate** / **exploratory**: Proposed vectors under evaluation; not yet ratified.

### Status Values

- `valid` — Ratified and required for conformance
- `proposed` — Candidate for inclusion; under evaluation
- `rejected` — Not accepted for this standard version
- `deprecated` — Previously valid; superseded by newer vectors

### Severity Levels

- **critical** — Must be satisfied for any claim of REG conformance
- **high** — Required for production deployments
- **medium** — Recommended for robustness
- **low** — Nice-to-have for completeness

### Phases

Vectors may apply to different execution phases:
- `pre-execution` — Input validation, policy evaluation
- `execution` — Core governance logic
- `post-execution` — Result handling
- `commit` — Audit record creation
- `audit` — Record inspection and analysis
- `recovery` — Failure handling and restart

## Contributing

### Adding a Vector

1. Choose the appropriate YAML file:
   - **core.yaml** for foundational behavior (coordinate with standards committee)
   - **extended.yaml** for advanced scenarios
   - **proposals.yaml** for candidates pending review

2. Create an entry with:
   - Unique `id` following the category prefix (e.g., `C6`, `R8`, `CT-R4-011`)
   - Clear `title` and `description`
   - At least one `assertion` describing what must be true
   - Appropriate `category`, `status`, and `severity`
   - Optional: `phase`, `tags`, `dependencies`, `rationale`, `spec_reference`

3. **Validate** your YAML against `schema.json`:
   ```bash
   python3 -c "import json; json.load(open('schema.json'))" && echo "Schema OK"
   ```

4. **Compile** the bundled artifact:
   ```bash
   python3 vectors/compile.py
   ```
   This creates `vectors/dist/vectors.json`.

5. **Submit** a pull request with:
   - Your new vector in the YAML file
   - Updated `vectors/dist/vectors.json` (generated by `compile.py`)
   - A brief explanation of the conformance requirement in the PR description

### Example Vector

```yaml
- id: C6
  category: core
  status: proposed
  title: "Example Vector Title"
  description: "Detailed description of the conformance requirement."
  phase: execution
  severity: high
  tags: ["tag1", "tag2"]
  assertions:
    - statement: "Specific assertion one"
      validation: observable
    - statement: "Specific assertion two"
      validation: auditable
  failure_mode: deny
  rationale: "Why this conformance rule matters."
  spec_reference: "REG Spec § X.Y"
  added_version: "1.1.0"
  dependencies: ["C1", "C5"]
```

## Vocabulary

### Assertion Validation Types

- **observable** — Can be directly observed (e.g., in logs, metrics)
- **measurable** — Can be quantified (e.g., latency, throughput)
- **auditable** — Found in audit records or traces
- **deducible** — Logically derived from other evidence

### Failure Modes

- **deny** — Execution is rejected
- **audit** — Decision is logged but may proceed
- **warn** — Warning emitted; execution continues
- **abort** — System halts to prevent inconsistency
- **retry** — Operation is attempted again with backoff

## Building the Lab Viewer

The lab viewer is a static HTML page that displays vectors from `vectors/dist/vectors.json`:

```bash
cd lab/
open index.html  # or: python3 -m http.server 8000
```

The viewer fetches and displays all vectors with filtering by category and status.
